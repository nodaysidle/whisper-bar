# Architecture Requirements Document — WhisperBar

## Document Purpose

Lock architecture boundaries, component ownership, runtime flows, state placement, platform lifecycle, persistence, security, integrations, and trade-offs without changing product scope.

## Architecture Summary

A privacy-conscious native macOS menu-bar speech-to-text utility that captures speech via push-to-talk or toggle recording, transcribes through an explicitly selected cloud service, and safely inserts or preserves the result. It keeps transcripts local, protects credentials, and never silently switches providers or incurs unexpected costs. The implementation uses the Native macOS SwiftUI Menu Bar contract in native runtime mode.

## Architectural Style

- Preset-owned Native macOS SwiftUI Menu Bar architecture
- Use an @main SwiftUI App entry with MenuBarExtra and Settings; one @Observable @MainActor MenuBarController owns menu, settings, HUD, and feature presentation while AppKit adapters remain in Platform owners.
- Run capture and provider work in cancellable actors or async tasks, keep exactly one active recording state machine, and publish UI state on the main actor.
- Vertical feature owners with explicit platform-boundary owners
- One-way feature and contract dependencies following the phase graph
- Local-first state unless product semantics explicitly require a remote service

## Runtime Boundaries

- FEAT-GLOBAL-HOTKEYS-AND-PUSH-TO-TALK-TOGGLE-MODES — Global Hotkeys and Push-to-Talk/Toggle Modes: Registers global hotkeys safely, detects conflicts, handles smooth release, and supports both push-to-talk and toggle recording modes.
- FEAT-MICROPHONE-CAPTURE-AND-FLOATING-HUD — Microphone Capture and Floating HUD: Captures microphone audio and displays a floating HUD with live input levels, elapsed duration, active mode, and instant stop/cancel controls.
- FEAT-DUAL-PROVIDER-ROUTING — Dual-Provider Routing: Routes audio to Deepgram for live WebSocket streaming with interim results and automatic finalization, or to OpenRouter for finalized audio batch transcription with optional text refinement using Gemini 2.5 Flash Lite.
- FEAT-PROVIDER-SELECTION-AND-COST-PROTECTION — Provider Selection and Cost Protection: Requires an explicit provider toggle before recording; never automatically switches providers or silently incurs costs.
- FEAT-SAFE-AUTO-PASTE-AND-CLIPBOARD-PRESERVATION — Safe Auto-Paste and Clipboard Preservation: After one successful final transcription and optional successful refinement, choose exactly one complete insertion candidate and apply the configured auto-paste, copy-only, or preview mode through the deterministic native macOS insertion contract; never insert partial, empty, failed, cancelled, or unapproved text.
- FEAT-LOCAL-HISTORY-AND-OFFLINE-SEARCH — Local History and Offline Search: Stores transcripts in bounded local storage with full-text search, copy, and atomic deletion; no transcripts are uploaded or synced to external clouds.
- FEAT-CUSTOM-WRITING-MODES-AND-VOCABULARY — Custom Writing Modes and Vocabulary: Feeds configurable prompts and terminology expansion deterministically into refinement and transcription requests.
- FEAT-CREDENTIAL-VAULT — Credential Vault: Stores credentials in secure macOS Keychain storage; never stores keys in UserDefaults, files, or application logs.
- FEAT-TEMPORARY-AUDIO-CLEANUP — Temporary Audio Cleanup: Writes audio to temporary sandboxed storage during recording and guarantees deletion immediately upon successful transcription or cancellation.

## Runtime Flows

1. Global Hotkeys and Push-to-Talk/Toggle Modes outcome: User presses the configured push-to-talk or toggle hotkey. → Registers global hotkeys safely, detects conflicts, handles smooth release, and supports both push-to-talk and toggle recording modes. → Start and stop dictation from any app using configurable global hotkeys without blocking system shortcuts.
2. Microphone Capture and Floating HUD outcome: Recording starts via hotkey. → Captures microphone audio and displays a floating HUD with live input levels, elapsed duration, active mode, and instant stop/cancel controls. → See capture state, audio levels, elapsed time, active mode, and stop/cancel actions in a minimal floating HUD.
3. Dual-Provider Routing outcome: User selects a provider before recording. → Routes audio to Deepgram for live WebSocket streaming with interim results and automatic finalization, or to OpenRouter for finalized audio batch transcription with optional text refinement using Gemini 2.5 Flash Lite. → Transcribe speech using live streaming or batch transcription, depending on the selected provider.
4. Provider Selection and Cost Protection outcome: User opens provider selection or starts recording. → Requires an explicit provider toggle before recording; never automatically switches providers or silently incurs costs. → Avoid unexpected costs by explicitly choosing a provider before recording.
5. Safe Auto-Paste and Clipboard Preservation outcome: Transcription completes successfully. → After one successful final transcription and optional successful refinement, choose exactly one complete insertion candidate and apply the configured auto-paste, copy-only, or preview mode through the deterministic native macOS insertion contract; never insert partial, empty, failed, cancelled, or unapproved text. → Insert transcribed text into the focused app while preserving the previous clipboard content.
6. Local History and Offline Search outcome: User opens history or searches for a transcript. → Stores transcripts in bounded local storage with full-text search, copy, and atomic deletion; no transcripts are uploaded or synced to external clouds. → Search, copy, and delete past transcripts stored locally without external sync.
7. Custom Writing Modes and Vocabulary outcome: User selects or edits a writing mode or vocabulary list. → Feeds configurable prompts and terminology expansion deterministically into refinement and transcription requests. → Apply configurable prompts and terminology expansion to refinement and transcription requests.
8. Credential Vault outcome: User enters or updates API credentials. → Stores credentials in secure macOS Keychain storage; never stores keys in UserDefaults, files, or application logs. → Store Deepgram and OpenRouter API keys securely without exposing them in files or logs.
9. Temporary Audio Cleanup outcome: Transcription succeeds or recording is cancelled. → Writes audio to temporary sandboxed storage during recording and guarantees deletion immediately upon successful transcription or cancellation. → Trust that recorded audio is deleted immediately after successful transcription or cancellation.

## Accessibility Boundary

- Require VoiceOver and keyboard operation for every control, expose stable accessibility labels, roles, values, and focus order, and verify with SwiftUI accessibility tests plus Accessibility Inspector.

## External Integration Placement

- Use one actor-owned URLSession boundary: URLSession.data(for:) for HTTPS requests and URLSessionWebSocketTask for streaming; encode and decode typed Codable DTOs, map failures before they reach UI state, and never expose raw response bodies.
- CON-INTEGRATION-DEEPGRAM-NOVA-STREAMING-TRANSCRIPTION: Deepgram WebSocket streaming is exclusively for live microphone audio. Open exactly one GET WebSocket to wss://api.deepgram.com/v1/listen with URLSessionWebSocketTask and model=nova-3 for each user-started live transcription; use typed Codable messages and never start another stream as an automatic retry or automatic paid retry. Failure: Authentication, rate, transport, provider, timeout, malformed-message, malformed-audio, cancellation, and empty-final failures are distinct privacy-safe terminal states; no automatic provider retry, automatic paid retry, paid fallback, history record, refinement, or insertion may follow them. Recovery: Preserve temporary audio only while awaiting explicit retry or explicit provider switch after a recoverable provider failure; keep completed transcript state visible and expose only copy, preview, or discard actions otherwise.
- CON-INTEGRATION-OPENROUTER-TRANSCRIPTION: Imported audio-file transcription uses the configured batch/file-capable provider, OpenRouter. Use POST https://openrouter.ai/api/v1/audio/transcriptions for one finalized audio input with default model openai/gpt-4o-transcribe. This is a batch final-transcription contract and produces no live partial results. Failure: Authentication, credit, permission, payload, timeout, rate, provider, decode, cancellation, and empty-transcript failures are distinct privacy-safe terminal states; none may create history or paste text. Recovery: Preserve the one finalized audio input only through the declared recovery decision, then allow an explicit retry or explicit provider change without an automatic paid fallback.
- CON-INTEGRATION-OPENROUTER-REFINEMENT: Use POST https://openrouter.ai/api/v1/chat/completions for optional non-live refinement with default model google/gemini-2.5-flash-lite, temperature: 0.0, reasoning: { effort: "none" }, and stream: false. Failure: Disabled, cancelled, timed-out, filtered, malformed, rate-limited, unauthenticated, empty, or non-stop refinement never replaces, deletes, or pastes over the accepted raw transcript. Recovery: Keep the raw transcript, expose an explicit refinement retry or use-raw action, and never make a second paid request automatically.

## Recovery Architecture

- Represent operations as idle, active, succeeded, failed, or cancelled and preserve the last valid user state.
- Use explicit user retries only; cancel tasks and close streams, file handles, delegates, and temporary resources on every terminal path.

## Packaging and Installation

- Scripts/package_app.sh is the sole packaging authority for release build, app assembly, resources, signing, strict verification, and DMG creation.
- Assemble one native arm64 macOS .app from the Swift Package Manager release executable, Info.plist, App.entitlements, and AppIcon.icns.
- Ad-hoc sign local builds or use an explicitly supplied Developer ID for distribution, then require codesign --verify --deep --strict.
- Register and launch the installed bundle through LaunchServices.
- Install the verified signed app at /Applications/WhisperBar.app after a scoped rollback copy, then register and launch that exact bundle through LaunchServices.
- Output artifact: native macOS .app and DMG
- Artifact path: dist/WhisperBar.app

## Architectural Trade-offs

- Preset fidelity is favored over cross-stack reuse.
- Deterministic owner and file mappings are favored over runtime plugin discovery.
- Durable local recovery is favored over transient simplicity.
- No server runtime is introduced.

## Architecture Review Checklist

- Every feature has one owner and one focused test.
- Every contract resolves to known features and one owner.
- Every modified file is created in an earlier phase.
- Persistence, permissions, credentials, lifecycle, recovery, packaging, and signing are explicit.
- No forbidden technology appears in an implementation decision.
